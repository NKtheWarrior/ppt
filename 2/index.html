05$ diff 2024 2026 --summary

What changed: attackers stopped breaking in the front door.

SHIFT 01
AI-assisted attacks
Exploit code, phishing copy and reconnaissance all got cheaper at once. The window between disclosure and a working exploit collapsed from weeks to days.
SHIFT 02
Supply-chain trust abuse
Why attack a hardened target when you can compromise something it already installs? One maintainer's token now reaches thousands of builds.
SHIFT 03
OAuth & third-party risk
Every SaaS and AI tool you connect holds a live key to your data. Your security is now the weakest vendor you trusted.

None of the four incidents ahead required a zero-day in the victim's own code. Three of them required no exploit at all.

09$ ./harden --target rsc

Prevention — React2Shell

Patch to the fixed versions — today, not this sprint
React 19.0.1 / 19.1.2 / 19.2.1 · Next.js 16.0.7+ · matching Vite, Parcel, Waku and RedwoodSDK releases
Put WAF rules in front of RSC and Server Function endpoints
Buys you coverage for the hosts you haven't patched yet — and for the next one of these
Validate strictly at every deserialization boundary
Treat anything rebuilt from the wire as hostile until it's been checked against a schema
Segment the network so RCE isn't game over
Your web tier should not be able to reach your database, your secrets store and your build system
Alert on anomalous outbound connections
Miners, tunnelers and downloaders all have to call home — that's the signal you can still catch

The uncomfortable part: patching was available on day one. The damage came from the gap between "a fix exists" and "we deployed it."

13$ ./harden --target dependencies

Prevention — supply chain

Lockfiles, plus a cooling-off period on new releases
Set minimumReleaseAge so a version has to survive in public before it reaches your build
Verify provenance, don't just trust the name
Generate an SBOM and check SLSA attestations — a stolen token can republish a package, but it can't fake the build origin
Restrict and audit install lifecycle scripts
Install with --ignore-scripts by default and allowlist the handful of packages that genuinely need them
Automate dependency scanning in CI
Snyk or equivalent, wired to fail the build — a report nobody opens is not a control
Rotate npm and GitHub tokens on a schedule
Every wave of this campaign ran on stolen long-lived tokens. Short-lived credentials break the loop
Least-privilege CI/CD credentials
Publish rights should be the exception, scoped to one package, and never sitting in a general-purpose runner

16$ ./harden --target third-party

Prevention — third-party trust

Least-privilege OAuth scopes — never "Allow All"
If a tool needs your whole mailbox to summarise one thread, that's the answer, not the ask
Allowlist and govern SaaS and AI tools
Employees will connect things. Decide in advance which things — an unreviewed integration is an unreviewed vendor
Encrypt every secret at rest, not just the "sensitive" ones
The env var nobody classified as sensitive is the one that ended up in the listing
Monitor OAuth grants tied to corporate SSO
Alert on new grants, broad scopes and offline access. Expire them on a schedule and make people re-consent
Shrink detection-to-disclosure
Two months of quiet access is not a detection problem you fix during the incident — it's one you fix before it

The lesson isn't "don't use AI tools." It's that every integration you grant becomes part of your attack surface, permanently, until you revoke it.

19$ ./harden --target public-sector

Prevention — credentials & configuration

Never hardcode credentials — client bundles are public
Anything you ship to a browser is published. Secret scanning in CI catches this before a stranger does
Real multi-factor auth with no bypass path
Test the bypass, not the happy path. Ask "what else can authenticate a session?" and remove every answer
Cloud storage: deny by default
No public or unauthenticated buckets — especially for scanned documents nobody thought of as a database
Audit vendors before deployment, not after disclosure
The organisation carries the risk even when the code was written by someone else
Hard boundary between staging and production
Test conveniences — like a master password — are exactly what survives into prod when the boundary is soft

And one process lesson: the initial denial cost more credibility than the vulnerability did. Reversing it within days was the right call — making it faster would have been better.

22$ ./harden --scope organisation

Five things to change on Monday.

Patch management cadence
A written SLA per severity — critical measured in hours, not sprints. React2Shell had a fix on day one; the damage was all in the delay
Zero trust for third-party integrations
Minimum scope, an expiry date, and a review. Every OAuth grant is a standing key to your data until someone revokes it
Dependency hygiene
Lockfiles, release-age delays, provenance checks, no unreviewed lifecycle scripts, scanning that fails the build
Credential hygiene
Rotate on a schedule, scope to one job, encrypt everything at rest, and never — ever — ship one to the client
Incident response readiness
Rehearse it before you need it. Decide now who discloses, how fast, and what you say — because denying it first is the expensive option

None of this is exotic. All four incidents were stopped by items on this list — in the organisations that had already done them.
